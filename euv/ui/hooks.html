输入与布局 Hook

eastspire2026/9/5大约 9 分钟euvuirustwasmcomponent-library

UseEuvInput

输入事件处理器工具集。提供 toggle、输入值绑定、复选框绑定、移动端键盘滚动等常用事件处理器。

切换布尔信号

use euv_ui::*;

let is_open: Signal<bool> = App::use_signal(|| false);

html! {
    euv_button {
        variant: EuvButtonVariant::Primary
        label: "Toggle"
        onclick: UseEuvInput::use_toggle(is_open)
    }
}

输入值绑定

自动识别 input、textarea、select 三种元素：

let text: Signal<String> = App::use_signal(String::new);

html! {
    input {
        r#type: "text"
        value: text
        oninput: UseEuvInput::on_input_value(text)
    }
}

Change 值绑定

html! {
    select {
        onchange: UseEuvInput::on_change_value(selected)
        option { value: "a" "A" }
        option { value: "b" "B" }
    }
}

复选框绑定

html! {
    input {
        r#type: "checkbox"
        onchange: UseEuvInput::on_change_checked(checked_signal)
    }
}

移动端键盘滚动

on_focus_scroll_into_view 和 on_blur_restore_height 用于解决移动端虚拟键盘遮挡输入框的问题：

input {
    onfocus: UseEuvInput::on_focus_scroll_into_view()
    onblur: UseEuvInput::on_blur_restore_height()
}
  • on_focus_scroll_into_view — 聚焦时等待键盘弹出后检查输入框是否被遮挡，必要时自动滚动
  • on_blur_restore_height — 失焦时移除滚动补偿

提示

所有方法返回 Option<Rc<dyn Fn(Event)>>，可直接用于 html! 的事件属性和组件 Props 的回调字段。

UseEuvLayout

布局工具，提供移动端视口管理、导航抽屉控制和安全区域处理。

UseEuvLayout 是零尺寸结构体，方法通过关联函数调用：

use euv_ui::*;

let layout: UseEuvLayout = UseEuvLayout;

use_resize

创建一个响应式信号，跟踪视口是否处于移动端模式，并订阅浏览器 resize 事件保持更新。resize 处理器有 16ms 防抖，监听器在 Hook 上下文清除时自动移除。

let is_mobile: Signal<bool> = UseEuvLayout::use_resize();

html! {
    if { is_mobile.get() } {
        div { "Mobile view" }
    } else {
        div { "Desktop view" }
    }
}

use_drawer_toggle

创建导航抽屉切换事件处理器，支持浏览器历史管理（打开时 pushState，关闭时 overlay_back 移除额外历史条目）。

let drawer_open: Signal<bool> = App::use_signal(|| false);

html! {
    euv_button {
        variant: EuvButtonVariant::Primary
        label: "Menu"
        onclick: UseEuvLayout::use_drawer_toggle(drawer_open)
        "Menu"
    }
}

use_safe_area_fix

注册全局事件监听器，解决 Android 全屏/沉浸模式下 env(safe-area-inset-*) 值失效的问题。在应用初始化时调用一次即可。

在初始化时，通过 sentinel <div> 读取当前 env(safe-area-inset-*) 的实际像素值并缓存到线程本地存储。当 fullscreenchange 或 resize 事件触发时，将缓存值直接写入应用根元素的 --safe-area-inset-* CSS 自定义属性，绕过 env() 可能返回的过时值。

同时处理原生全屏（如 <video> 全屏按钮）导致的浏览器历史问题：全屏进入时自动 pushState，系统返回按钮通过 popstate 守卫退出全屏而不导航到上一页。

// 应用初始化时调用一次
UseEuvLayout::use_safe_area_fix();

apply_cached_insets

将缓存的安全区域像素值写入应用根元素和 Canvas 全屏容器的 CSS 自定义属性。通常在需要手动刷新安全区域值时调用。

UseEuvLayout::apply_cached_insets();

提示

use_safe_area_fix 应在应用初始化时调用一次，之后全屏切换和视口变化时会自动维护安全区域值。apply_cached_insets 在需要手动刷新时使用。

原生 Hook 工具集

euv-ui 在 ui/src/hook/ 下提供了一组更底层的、面向状态机的 Hook 工具，涵盖计数器、防抖/节流值、错误边界、表单状态、国际化、懒加载、前值记录、性能分析、Suspense、过渡动画和异步任务执行。这些工具通过顶层函数（use_xxx()）调用，与 App::use_signal / App::use_node_ref 等核心 Hook 共存。

提示

下面所有 Hook 默认接受当前 HookContext 作为作用域。同一个 Hook 在同一组件同一调用位置会返回同一个状态对象，无需手动管理生命周期。

Toggle

一个轻量的响应式布尔开关，封装了 Signal<bool> 的最常见用法。Toggle::new() 构造初值 false；调用 set_true / set_false / toggle / set(next) 触发值变更。当前值通过 get() 快照读取，反应式读取走 get_value() 拿到的 Signal<bool>：

use euv_ui::*;

let toggle: Toggle = Toggle::new();
toggle.toggle();
assert_eq!(toggle.get(), true);

html! {
    button {
        onclick: move |_| toggle.toggle()
        if { toggle.get_value().get() } { "ON" } else { "OFF" }
    }
}

主要方法：set_true / set_false / toggle / set(next: bool) / get() -> bool / get_value() -> Signal<bool>。

Counter

带上下界和步长的有界整数计数器。构造签名 Counter::new(min: Option<i32>, max: Option<i32>, step: i32)，i32 边界可通过 None 表示无限制：

use euv_ui::*;

let counter: Counter = Counter::new(
    Some(0),     // min
    Some(100),   // max
    1,           // step
);
counter.increment();
counter.set(50);

html! {
    button {
        disabled: counter.is_at_max()
        onclick: move |_| counter.increment()
        "Count: " { counter.get() }
    }
}

主要方法：increment / decrement / set(next: i32)（会自动 clamp 到 [min, max]）/ set_unchecked(next)（绕过 clamp）/ is_at_max / is_at_min / get() -> i32 / get_value() -> Signal<i32>。

Previous

记录上一次渲染时某个表达式的值，便于"上次 vs 当前"的比较：

use euv_ui::*;

let count: Signal<i32> = App::use_signal(|| 0);
let prev: Previous<i32> = use_previous();

let on_change = move |_| {
    prev.record(count.get());
};

html! {
    div {
        "current: " { count.get() }
        " previous: " { prev.get_previous_snapshot().map(|v| v.to_string()).unwrap_or_default() }
    }
}

主要方法：Previous::new() / record(value) / get_previous_snapshot() -> Option<T> / clear()。

首次 record 调用之前 get_previous_snapshot() 返回 None；之后返回 Some(previous_value)。clear() 清空记录。

DebouncedValue

只在静默期结束后才提交新值的"防抖"包装器。与 App::use_interval 配合使用：interval 回调周期性调用 tick(now_ms)，由 hook 决定何时真正提交。

use euv_ui::*;

let search: DebouncedValue<String> = use_debounced_value::<String>(200);  // 200ms 防抖
let query: Signal<String> = App::use_signal(String::new);

let _ = App::use_interval(20, move || {
    let now_ms: u64 = js_sys::Date::now() as u64;
    search.tick(now_ms);
});

// 用户每次输入都调用 set；hook 会等待 200ms 静默期后再提交
search.set(query.get(), js_sys::Date::now() as u64);

主要方法：set(next: T, now_ms: u64) / tick(now_ms: u64) -> bool（返回是否触发了提交）/ cancel() / get() -> T / is_pending() -> bool。

ThrottledValue

每隔固定时间窗口提交一次当前值的"节流"包装器。与 DebouncedValue 的区别在于：节流是周期性强制提交，防抖是等静默期。

use euv_ui::*;

let scroll: ThrottledValue<f64> = use_throttled_value::<f64>(50);  // 50ms 节流窗口
scroll.set(123.4, js_sys::Date::now() as u64);

主要方法：set(next: T, now_ms: u64) / tick(now_ms: u64) -> bool / cancel() / get() -> T / is_throttling() -> bool。

ErrorBoundary

包装可能 panic 的子树并捕获错误。父组件读取 get_phase()（返回 Signal<ErrorBoundaryPhase>）决定渲染子节点还是降级 UI。ErrorBoundaryPhase 只有两态：Healthy / Caught(String)。

use euv_ui::*;

let boundary: ErrorBoundary = use_error_boundary();

let result: Result<String, String> = boundary.try_with(|| {
    // 可能 panic 的闭包
    "ok".to_string()
});

html! {
    match { boundary.get_phase().get() } {
        ErrorBoundaryPhase::Healthy => { render_normal() }
        ErrorBoundaryPhase::Caught(_) => { render_fallback() }
    }
}

主要方法：ErrorBoundary::new() / try_with(closure) -> Result<R, String>（panic 后转入 Caught，返回 Err）/ report_error(&str) -> String（不依赖 panic，直接喂错误）/ reset() / get_phase() -> Signal<ErrorBoundaryPhase>。

FormState

聚合的表单状态，每个字段维护 value / error / submitting 三个独立 Signal。通过 HookContext::form()（来自 HookContextFormExt 扩展 trait）获取。

use euv_ui::*;

let form: FormState = HookContext::form();

let on_submit = move |event: Event| {
    event.prevent_default();
    form.submit(
        &validators,
        move || {
            // 提交逻辑
        },
    );
};

html! {
    form {
        onsubmit: on_submit
        input {
            r#type: "text"
            value: form.field("name")
            oninput: move |event: Event| {
                let value: String = event.target().unwrap().dyn_into::<HtmlInputElement>().unwrap().value();
                form.set_field("name", &value);
                form.touch("name");
            }
        }
        if { form.is_touched("name") && !form.error("name").is_empty() } {
            span { form.error("name") }
        }
        button {
            r#type: "submit"
            disabled: form.get_submitting().get()
            "Submit"
        }
    }
}

主要方法：field(name) -> String / error(name) -> String / is_touched(name) -> bool / set_field(name, value)（同时标 touched 并清掉旧 error）/ touch(name)（仅标 touched）/ validate(&validators) -> bool / submit(&validators, on_submit) -> bool / reset() / error_count() -> usize / get_submitting() -> Signal<bool>。

注意

FormState 的工厂入口是 HookContext::form()（来自 HookContextFormExt 扩展 trait）—— 必须在 html! 渲染闭包内调用以获得正确的 HookContext。直接 FormState::default() 也可以用，但所有字段都是空 map / 空 set / false，需要自己 set 才能用。在事件回调中使用时直接复用已绑定的实例即可。

LazyComponent

延迟构造的组件包装器，第一次访问 get() 时才调用工厂函数。

use euv_ui::*;

let lazy: LazyComponent<String> = use_lazy_component::<String, _>(|| {
    // 首次访问时执行（可能很昂贵）
    "computed".to_string()
});

// 触发预加载但不使用结果
lazy.prefetch();

// 在 html! 中按需渲染
match { lazy.loaded() } {
    Some(value) => { div { value } }
    None => { div { "Loading..." } }
}

主要方法：LazyComponent::new(factory) / prefetch() / get() -> Option<T>（首次调用时执行 factory）/ loaded() -> Option<T>（不触发 factory，仅读取已加载值）/ reset() / change_factory(factory)。

ProfilerHandle

轻量级性能分析器，记录任意代码段的耗时。所有条目存在 get_entries() 返回的 Signal<Vec<ProfileEntry>> 里，组件可以直接订阅它并显示。

use euv_ui::*;

let profiler: ProfilerHandle = use_profiler();

let result: String = profiler.measure("compute", || {
    expensive_computation()
});

// 或使用 split-timer API
let mark: ProfilerMark = profiler.begin("network");
fetch_data().then(|_| mark.end());

主要方法：ProfilerHandle::new_with_empty_entries() / measure(label, f) -> R（同步闭包，自动计时）/ begin(label) -> ProfilerMark（异步 / 跨作用域计时，配合 ProfilerMark.end(self) 消费）/ clear() / get_entries() -> Signal<Vec<ProfileEntry>>；ProfileEntry { label: String, elapsed_ms: f64, timestamp_ms: f64 }。

SuspenseHandle

异步等待句柄，用于包装"等待资源 → 渲染数据 / 错误"的模式。get_phase() 返回 Signal<SuspensePhase<T>>，三态：Pending / Resolved(T) / Failed(String)。

use euv_ui::*;

let suspense: SuspenseHandle<String> = use_suspense::<String>();

suspense.resolve_sync("data".to_string());
// 或
suspense.fail("network error".to_string());
suspense.reset();

html! {
    match { suspense.get_phase().get() } {
        SuspensePhase::Pending => { div { "Loading..." } }
        SuspensePhase::Resolved(value) => { div { value } }
        SuspensePhase::Failed(err) => { div { err } }
    }
}

主要方法：SuspenseHandle::new() / resolve_sync(value) / fail(message) / reset() / get_phase() -> Signal<SuspensePhase<T>>。

TransitionState

过渡动画的状态机：在 Exited / Entering / Entered / Exiting 四个阶段间切换，每帧通过 tick(elapsed_ms) 推进。通过 HookContext::transition(config)（来自 HookContextTransitionExt 扩展 trait）获取。

use euv_ui::*;

let transition: TransitionState = HookContext::transition(TransitionConfig {
    enter_ms: 200,
    exit_ms: 150,
});

transition.enter();
// 在 use_interval 回调中推进
let _ = App::use_interval(16, move || {
    transition.tick(16);
});

html! {
    if { transition.is_animating() } {
        div { "animating, progress: " { transition.get_progress().get() } }
    }
}

主要方法：enter() / exit() / toggle() / change_config(config) / tick(elapsed_ms: u32) / tick_until_done(step_ms: u32) / reset() / duration_for(phase) -> u32 / remaining_ms() -> u32 / is_animating() -> bool / get_phase() -> Signal<TransitionPhase> / get_progress() -> Signal<f64> / get_config() -> Signal<TransitionConfig>。

UseAsyncHandle

异步任务执行句柄：传入 Future 工厂，在后台异步执行，通过 state() 暴露 AsyncState<T, L>，支持重新拉取。取消是自动的：当 hook 上下文销毁（组件 unmount 或 match-arm 切换）时，UseAsyncSlot 的 Drop 会自动翻转取消标志，正在运行的 future 看到标志后不再写回 state。

use euv_ui::*;

let handle: UseAsyncHandle<String, ()> = use_async::<String, ()>();

handle.refetch::<_, _, String>(|| {
    // 返回一个 Future<Output = Result<T, E>>；Err 必须能 Into<String>
    async move {
        // ...真实异步逻辑（fetch / wasm_bindgen_futures::JsFuture 等）...
        Ok::<String, String>("done".to_string())
    }
});

html! {
    match { handle.state() } {
        AsyncState::Loading(_) => { div { "Loading..." } }
        AsyncState::Ok(value) => { div { value } }
        AsyncState::Err(err) => { div { err } }
    }
}

主要方法：state() -> AsyncState<T, L>（owned 快照，调用时直接 get 当前值）/ set_state(next: AsyncState<T, L>)（测试时手动覆盖状态）/ refetch<F, Fut, E>(factory: F) 其中 factory: FnOnce() -> Future<Output = Result<T, E>> 且 E: Into<String>。

AsyncState 的三态为：Loading(L) / Ok(T) / Err(String)。L 是任意满足 HasLoadingHint 的类型，用于在加载时携带前一帧的占位数据；最常见的实例化是 ()。

I18n

聚合的国际化状态：当前语言、回退语言和翻译表。t(key) 返回当前 locale 的翻译文本，缺失时回退到 fallback_locale。

use euv_ui::*;

let i18n: I18n = use_i18n("en");

i18n.add_messages("en", &[("hello", "Hello, world!"), ("bye", "Goodbye!")]);
i18n.add_messages("zh-CN", &[("hello", "你好，世界！"), ("bye", "再见！")]);

let change_to_zh = move |_: Event| i18n.change_locale("zh-CN");

html! {
    button {
        onclick: change_to_zh
        i18n.t("hello")
    }
}

主要方法：change_locale(locale: &str) / change_fallback_locale(locale: &str) / add_messages(locale: &str, entries: &[(&'static str, &'static str)]) / 顶层便利函数 i18n_register(handle: I18n, locale: &str, entries: &[(&'static str, &'static str)]) / remove_locale(locale) / remove_message(locale, key) / t(key) -> String / t_with(key, vars: &HashMap<&str, &str>) -> String / locale_count() -> usize / active_message_count() -> usize。

提示

所有 Hook 都设计为幂等的：同一个 Hook 在同一组件同一调用位置每次渲染返回的是同一个状态对象；不要把它们当作"普通函数返回值"重新构造，否则会丢失之前的状态。
